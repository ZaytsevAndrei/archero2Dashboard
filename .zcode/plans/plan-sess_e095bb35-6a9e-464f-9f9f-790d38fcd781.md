## Что делается

Новый порядок: скрины принимаются **только от допущенных игроков** (список ведёт Dragon на сайте), и бот обрабатывает **альбомы** картинок, записывая **всех игроков**, видных на каждом скрине (каждую строку «ник + урон» рейтинга гильдии).

## 1. `docs/config.json` (новый файл)

```json
{ "admins": ["176147068"], "submitters": [] }
```
`submitters` — допущенные отправители: `{ "tgId": "123", "nick": "Nick", "tgUsername": "@u", "clan": "unity2", "added": "2026-10-07" }`. Стартуем с пустым списком (Dragon как админ допущен всегда), остальных Dragon добавит через админку. Файл публичный — уровнем exposures как data.json (id и так там видны).

## 2. Админка `docs/admin.html` + `docs/admin.js` (новые)

Страница на русском (для Dragon), стили переиспользуем из style.css:
- **Токен**: поле ввода, хранится в localStorage, проверка через `GET /user`. Один раз создаётся fine-grained PAT (только этот репозиторий, Contents: Read and write) — инструкция будет на странице и в README.
- **Таблица допущенных**: ник, Telegram ID, @username, клан, дата; кнопка «Удалить». Форма добавления: ник, ID, @username, клан (UNITY/UNITY2).
- **Помощник**: страница грузит data.json и показывает всех существующих пользователей (ник, id, @username, клан) с кнопкой «Добавить» — не надо искать ID руками.
- **Админы**: просмотр + добавить/удалить ID.
- **Сохранение**: GitHub Contents API — `GET docs/config.json` (sha) → `PUT` нового содержимого, при конфликте sha повтор с свежими данными.

## 3. `scripts/poll.mjs`

- **Загрузка конфига**: `loadConfig()` с дефолтом `{admins:[OWNER_CHAT_ID], submitters:[]}` + валидация. Обновление: при старте, после каждого успешного `pushData()` и раз в 10 минут — `git pull --rebase origin main` при чистом рабочем дереве, затем reload (mtime-check). Бот config.json никогда не пишет, коллизий нет.
- **Гейт** в начале `handleMessage`: не админ и не из списка → в личке вежливый отказ (не чаще раза в 12 ч на человека), в группе молча; плюс **уведомление всем админам** «Запрос доступа: Имя @username id123» (раз в 24 ч на человека). Маркер — новый ключ `data.denied` (добавить в `DATA_KEYS`). Саморегистрация через /start для чужих становится недоступна — так и задумано.
- Зарегистрированному отправителю из списка молча проставляем клан из списка (обход надоедливого переспроса клана).
- **Альбомы**: буфер фото по `media_group_id` (сейчас не обрабатывается вовсе — фото альбома перезаписывают запись друг друга). Отправка на обработку: по таймеру 3 с после последнего фото группы, в конце каждой пачки апдейтов, и одно дополнительное `getUpdates timeout:0` перед флешем, чтобы док catch хвост альбома. Один итоговый ответ на весь альбом.
- **`processAlbum()`**: для каждой картинки — `downloadProof`, `ocrBoard()` (новая функция, см. п.4), канонизация ников, запись; `saveData` после каждой картинки (краш-безопасность). Если ничего не распознано и отправитель зарегистрирован — фолбэк на старый `ocrOwnRow` по его нику.
- **Канонизация ника**: точное нормализованное совпадение, затем Левенштейн ≤ `max(2, 0.34·len)` против известных ников (users + submitters + исторические записи); при споре двух ников — не сопоставляем. Незнакомый ник записывается как распознался (паттерн 2–24 симв., буквы/цифры/_.-) — виден в ответе бота.
- **Клан записи**: клан игрока из users/списка, иначе клан отправителя, иначе unity2.
- **Записи**: новые поля `via` (tgId отправителя) и `grp` (id медиагруппы); дедуп по `ник+дата+клан` (перезапись за тот же день). Присылающий сам свой скрин по-прежнему записывается (его строка есть на скрине).
- **/undo**: удаляет весь последний альбом отправителя (по `grp`), не по одной записи; старое поведение остаётся для собственных записей.
- **/stats**: учитывать записи и по `tgId`, и по совпадению ника.
- `/bug`-уведомления — всем админам из конфига.

## 4. `scripts/ocr.mjs`

- Рефакторинг: общая预处理 (кроп/масштаб/recognize/groupLines) в внутренний хелпер — `ocrOwnRow` не меняется по поведению.
- Новый экспорт **`ocrBoard(imagePath)`** → все строки рейтинга `[{nickRaw, dmg, raw, y}]`: урон через существующий `parseDamageToken`/склейку суффиксов, ник — буквенные токены левее урона с чисткой мусора («+¥DonMaxone»).
- Новый экспорт **`matchNick(raw, knownNicks)`** — канонизация (см. выше).

## 5. `scripts/i18n.mjs`

Новые строки ru/en: отказ в доступе, запрос доступа админам, итог альбома («✅ Скринов: 10, игроков записано: 23 … ⚠️ Не распознаны: …»), правка /help.

## 6. Регрессия OCR (обязательно по AGENTS.md)

`scripts/regression-ocr.mjs` расширить: для каждого живого пруфа из data.json — `ocrBoard` + `matchNick(entry.nick)` должен найти строку с `dmg === entry.dmg`. Прогнать по всем пруфам, до чистого прохода итерируем эвристики (склейка, чистка мусора, допуски).

## 7. `docs/index.html` и `README.md`

Небольшая ссылка «⚙ Админка» в подвале → admin.html. README: новый порядок, схема config.json, инструкция по токену.

## Совместимость сайта

app.js менять не нужно: дедуп по `nick|date`, клан и пруфы у записей есть, `tgId` сайт не использует.
